What it is

Rationale that survives the handoff

AI agents help write code, but the reasoning behind it often stays in prompts, chats, and disconnected documents. Axiom defines the domain, policies, and workflows that keep those connections — exercised in this repository through a Codex harness and a Go implementation.

  • 01

    Intent gets lost

    Specifications

    Outcomes, constraints, and acceptance criteria are recorded before code is written.

  • 02

    Context fragments

    Projects

    A Project relates independent repositories without treating any single one as the whole.

  • 03

    Decisions drift

    Plans & ADRs

    Plans and architecture decisions become durable references for humans and agents alike.

  • 04

    Completion lacks proof

    Evidence

    Validation and Evidence make results inspectable and reproducible, not merely asserted.

Spec-Driven Development. The reason for a change stays connected to its implementation and its acceptance evidence.

How it works

One lifecycle, for people and for agents

Each step produces the context the next step consumes.

  1. 01

    Specify

    Intent becomes a Specification with outcomes, constraints, and acceptance criteria, before any code.

  2. 02

    Plan

    Decisions and the plan are recorded; architecture choices with lasting impact become ADRs.

  3. 03

    Execute

    Implementation runs in bounded Executions on Codex or Claude, and material choices wait for human approval.

  4. 04

    Validate

    Validation and review produce Evidence and reconcile the docs. Acceptance remains a human decision.

Today each step is driven by humans together with the harness and the Runtimes. Dynamic orchestration remains future work.

Installer

Install from the terminal

The commands from the Getting Started guide, from install to your first workflow.

# macOS or Linux: install the latest stable release

$ curl -fsSL https://raw.githubusercontent.com/rgomids/axiom/main/scripts/install.sh | sh

# Windows client edition, amd64: 64-bit PowerShell 5.1+

PS> & ([scriptblock]::Create((Invoke-RestMethod https://raw.githubusercontent.com/rgomids/axiom/main/scripts/install.ps1)))
PS> $env:PATH = "$env:LOCALAPPDATA\Axiom\bin;$env:PATH"

# verify the installation

$ axiom version
$ axiom help

# install or upgrade user-global skills

$ axiom first-run

# relate repositories to one Project

$ axiom project configure
$ axiom project show --selector my-project

# run the bounded workflow for Issue #123

$ axiom workflow start --project my-project --repository main --number 123
$ axiom workflow status --project my-project --repository main --number 123

Eligible hosts: macOS arm64, Linux amd64/arm64, and Windows client editions on amd64 with 64-bit PowerShell 5.1+. Windows Server is unsupported; numeric OS versions are not installation filters. The Windows PATH command affects only the current terminal. Full Getting Started guide.

Windows requires local NTFS and safe permissions, including ancestor directories. If you see unsafe project storage, choose an eligible location with -BinDir and -ReceiptDir and adjust PATH. This does not relocate state or skills; reinstallation can also fail with upgrade: state_unsafe. See the Windows example and troubleshooting.

Getting started

From install to your first workflow

Using Axiom needs no clone, Go toolchain, or build.

  1. 01

    Install

    The installer verifies the SHA-256 checksum before extracting and installs axiom into $HOME/.local/bin, without sudo.

  2. 02

    Verify

    axiom version reports the installed version and revision.

  3. 03

    First run

    axiom first-run finds Codex and Claude on your PATH and installs Axiom's skills for each. It never installs a Runtime or touches credentials.

  4. 04

    Configure a Project

    Guided: it previews the exact change and writes nothing until you answer yes.

  5. 05

    Run the workflow

    Create a Work Item as a GitHub Issue, then start and inspect its bounded workflow.

Foundation & discovery

A solid foundation — and room to evolve

Axiom already connects intent, execution, and evidence in a controlled flow. The next capabilities are explored through discovery before they become product commitments.

Available foundation

What Axiom already provides.

  • Local, deterministic control plane

    Axiom governs the workflow while agents act within explicit limits;

  • Projects independent of Repositories

    Organise a product's context without confusing the logical project with source code;

  • Intent-driven workflow

    Connecting Specification, decisions, planning, implementation, validation, and Evidence;

  • Agent runtime integration

    Skills and adapters that keep the process rules inside Axiom;

  • Work Items in the development flow

    Preserving traceability between request, execution, and result;

  • Evidence and provenance as part of delivery

    Review what happened without relying only on the agent's claim;

  • Local installation and state

    Keeping configuration, execution, and control close to the operator's environment.

Evolutions in discovery

Hypotheses under research, not promised features.

  • Multi-runtime and multi-agent orchestration

    Choose, combine, and switch agents and runtimes by capability, cost, availability, context, and execution policy;

  • Customisable development pipelines

    Define stages, agents, human gates, retries, parallelism, and expected Evidence for different kinds of work;

  • Per-stage configuration

    Select Runtime, Model Profile, reasoning effort, and specific context for each workflow stage;

  • QA as a first-class capability

    Run specialised validation — functional, integration, security, accessibility, and UI automation tests — with structured Evidence;

  • Graphical control plane

    Follow Projects, Work Items, Executions, agents, gates, Evidence, failures, and many active jobs through a visual interface;

  • Isolated workspaces for parallel executions

    Explore Git worktrees so several agents can work at once without sharing the same working directory;

  • Secrets and operator identity

    Manage credentials securely, with protected storage, authentication, auditing, and access control;

  • Specialised probabilistic decisions

    Explore mechanisms such as Jev/System One for routing, agent selection, classification, and confidence-based gates, without replacing deterministic rules;

  • Documentation for humans and agents

    Evolve the public documentation into a Git-native experience, navigable by people and efficient for AI agents to consume.

Discovery is not a commitment to implement. Future capabilities are researched, tried, and validated before they are promoted to Specifications and versioned decisions.
