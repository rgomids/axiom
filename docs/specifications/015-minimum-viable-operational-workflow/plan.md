## Selected technical design

### TD-01 — Aggregate, persistence and fencing

Use one versioned `Execution` aggregate in `internal/workflow`, one `WorkflowStore` implementation in `internal/local`, and one engine in `internal/stageexecution`. Reuse these package boundaries rather than add an executor service/package. Use a new explicit wire discriminator `kind: execution`, `formatVersion: 4`, under `executions/v2`; never decode old bytes as the new type. This is a Plan-selected new contract, not an implemented format. Existing Execution versions and Graph/Single formats remain inert.

Aggregate fields: identity (Execution, Project, Work Item and repository-key bindings); immutable selected Workflow snapshot and digest; revision; runner generation; stage/task dependencies and validated outcomes; immutable attempt invocation/authority snapshots; attempt/process identity, timeout and cancel intent; confirmed/unknown effects; bounded message facts; repository artifact/Evidence references; delivery observations and rework links. No child Executions or separate operational graph/plan/policy/packet truth. Logs and large artifacts are private append-only content referenced by digest/identity; they cannot advance state. Bound record size, message size and artifact reference validation explicitly in the codec; refuse oversized input rather than truncate truth. Start with existing bounded storage limits and deterministic oversize diagnostics; increase only with measured fixture evidence.

Serialize aggregate updates with existing anchored directory lock and expected-revision CAS. A single exclusive runner lease controls dispatch; persist its monotonic generation in Execution. Lock order is runner lock then aggregate lock; status reads never acquire a runner lease. Every state/result/message commit checks Execution/task/attempt identity, expected revision, runner generation and current cancellation/authority. Losing CAS reloads and recomputes eligibility; never repeats a spawned effect. A stale runner cannot publish or authorize a successor. Parallel completions enter the principal writer serially; no independent child writer/store. Preserve rooted path/no-symlink protections and existing private permissions.

Prepare private bytes, validate, protected replace at one commit point using ADR-0007 primitives; make artifact content durable before publishing its reference. Failed preparation leaves no state transition; missing/corrupt referenced content reports recovery_required, never success. Preserve crash recovery markers only where the reused publication primitive requires them; do not retain a second operational receipt lifecycle. Unit fault tests must verify process-local and filesystem failure windows; no stronger cross-platform power-loss guarantee is inferred.

Alternative: retain Graph/Single and project a facade. Rejected because two authority writers and recovery paths remain. A new database or event-sourcing subsystem adds dependencies without evidence. A bounded JSON aggregate trades rewrite/contention cost for simpler ownership; reconsider only against measured size/latency, never by silently introducing another truth owner.

### TD-02 — One run path and invocation binding

One public `workflow run` resolves the linked Work Item, selected Workflow, repository targets, effect bounds and per-agent inputs, creates/loads Execution and drives the engine. Read-only status/log inspection plus cancel/retry/reconcile remain useful operations; no required public start→plan→stage preview→apply→advance sequence. This is the planned replacement CLI, not a currently available command. Preserve the canonical JSON completion envelope and update installed docs/skills/metadata together with parsers. Unknown retired commands/flags fail with a bounded replacement diagnostic; no compatibility executor.

Per field precedence: explicit per-agent run override > explicit Workflow agent value > explicitly configured machine-local default. At each level Profile supplies optional defaults, and explicit fields replace that default. Distinct same-level sources conflict; missing/ambiguous Runtime/model/effort/instructions refuses. Effort may explicitly be `runtime-default`; it never asserts a concrete vendor level. Profiles are optional, never generated to dispatch. Freeze Runtime identity, selected executable reference, model, effort, instructions, safe input provenance and optional Profile digest before spawning. Reject inherited effective selector conflicts; never silently substitute a Runtime/model/effort or infer capability/complexity. Retry preserves the tuple unless a newly authorized explicit selection creates another attempt. Current target/effect revocation still applies.

Keep one bounded effective-input reader from `runtimeadapter/effort_sources.go`; remove auth-status preflight from run. Before changing its consumers, compare `authpreflight` and `effort_sources` fixtures by required selector: retain safe override/argv detection, malformed/unsafe source diagnostics and redaction, delete status/support prediction and duplicate parsers. Optional diagnostic auth inspection may survive only with a named docs/command consumer and safety test; it must never be called by run. Vendor/spawn/auth/option errors are observed attempt failures with sanitized repair guidance, not eligibility certification. No new parser dependency.

### TD-03 — Scheduling, messages and integration

Compile dependencies in memory from the retained Workflow; same scheduler handles one or many agents. Ready means dependencies have validated outputs, applicable human gates/effect authority are satisfied, no unresolved unknown effects and no cancellation. Persist attempt preparation under fence before launch, then observe running/terminal state. A crash after preparation or spawn without correlated terminal evidence is unknown/recovery_required; do not respawn automatically. Exit zero requires output validation; missing output fails. Eligible next work progresses automatically; configured human gates require real facts, never generated approval. Cycle/unknown dependency validation occurs before any spawn.

Messages are bounded attempt-owned facts with ID, sender, recipient, reply-to/correlation, kind and observed disposition. Retain question, answer, blocker and result kinds with named consumers (conversation routing, waiting dependency diagnosis, output validation). Progress is a log; artifacts are references. Delete contract/dependency-resolution variants without a distinct consumer. Bind private ingress to launcher-issued task context; child payload cannot choose its sender or authority. Deduplicate IDs/replies; reject forged identity, stale generation, wrong recipient/attempt, oversized payload and post-cancel result. A message never grants permission or establishes another agent's success. Codex and Claude adapters consume the same task/message contract; no vendor-specific operational store.

S1 includes a bounded two-stub ingress contract fixture to close L's identity gap; S2 delivers parallel scheduling and bidirectional collaboration. For agents editing one repo recommend independent Git Worktrees/branches. Record repository identity, base SHA and agent result SHA; principal owns the integration branch and serializes integration with an expected integration HEAD. Dirty/changed base or conflicts stop integration explicitly. Preserve branches/results, resolve conflicts under scoped authority, rerun relevant post-merge checks and record final SHA before integrated. Failed checks remain not_integrated. Worktrees do not fence shared external resources; use current aggregate authority/fencing and resource-specific serialization. No automatic destructive reset or cleanup of user worktrees.

### TD-04 — Delivery, Evidence and recovery

One Execution-owned delivery record holds per-repository readiness/artifact refs, authorized remote target/effect bounds, observed push/PR identifiers, unknown outcome and human disposition. Derived packet/export is read-only, not another store. Local result completion needs no PR. Before each remote mutation verify current authority, repository/remote/ref/base/head and recorded result readiness. New target/effect needs authorization; an existing exact bounded grant does not need ceremonial repetition. Agent output cannot approve publication, merge, release, acceptance or closure.

Persist mutation intent before the call, then correlated outcome. On timeout/lost response report unknown and inspect the exact remote target under authority; never blindly push/create again. Reconcile appends observed facts without overwriting the uncertain history. Explicit retry requires known disposition, valid authority and another attempt; failed/unknown workspace effects require explicit preservation/reset disposition, never implicit reset. Rejection keeps immutable results/findings and creates a linked rework Execution using the same engine, without Packet/Decision/Rework objects or transferred permission. Only actual human disposition can mark acceptance; technical completion cannot.

Evidence records classification (deterministic simulation vs actual operation), exact source SHA, fixture/check command, inputs digest, target keys, attempt/result correlation, confirmed/unknown effects, exit/output validation and artifact digests. Logs, process exit and agent assertions stay distinguishable. Credentials/unsafe env/absolute private paths are not portable Evidence. Cancellation persists intent, fences further scheduling and signals only verified owned process scope; report requested vs observed stop. Retain ADR-0028 PID/start/process-group identity and known escape veto; escaping descendants remain an explicit limit. Never signal a reused PID or equate process stop with reversal of external effects.

## Breaking cutover and rollback

This Plan performs no inventory of private installed state and no process stop. S1 implementation prepares a read-only operator checklist/tool output using existing inspection surfaces before retirement; no permanent legacy execution reader/service. At the authorized deployment boundary:

1. Stop new starts/writers; identify exact installed source/binary, Project/state roots and owned attempts from existing deployment records. Inventory active processes, leases/attempt IDs, unresolved local/remote effects and publication intents. Unknown inventory completeness BLOCKS cutover. Record sanitized counts/dispositions, not state dumps in Git.
2. Before deleting/replacing state, copy raw bytes privately where feasible with permissions, manifest/checksum and restore location; verify readability/byte identity, never import backup into the repository. Backup does not establish stopped processes. If backup is infeasible, report why and require a disposition before destructive switching; no silent data loss.
3. Safely stop only verified owned processes with existing controls. Confirm main/group identity, terminal observation and effect disposition. Active/uncertain/escaped work or unknown remote mutation BLOCKS cutover pending explicit disposition; never replay it. No kill based solely on stale PID.
4. Only after resolved disposition enable the new namespace and new-format-only starts. Refuse old resume/retry/foreign writes with actionable breaking-cutover diagnostic. No conversion, migration, old binary sidecar, compatibility reader UI or legacy dispatch fallback. Published receipts remain facts.
5. Verify new source with isolated fixtures before deployment. Actual cutover evidence is NOT_RUN here and is required before switching real state. Do not run product E2E or live Runtime validation to authorize it.

Rollback before switching restores prior binary/state only after safe-stop/disposition under separate operational authority. After new Executions/effects exist, stop new work and preserve both namespaces; do not run an old binary against new state, resume old attempts or replay effects. Prefer a forward fix; restoring inert backup is investigation, not execution authority. Filesystem atomic replace is not an external transaction. Cutover is blocked if the operator cannot establish a safe boundary.
