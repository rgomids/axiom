# Command Deprecation NNNN — Short name

## Status

`Proposed`

Allowed lifecycle: `Proposed -> Approved -> Deprecated -> Removed`.

## Affected command

State the documented command exactly.

## Replacement

State the replacement command or explicitly state that no replacement exists.

## Rationale

Explain why deprecation is needed.

## Affected users

Describe affected users and expected impact.

## Migration steps

List complete steps users must follow.

## Notice or release target

Identify the release containing the deprecation notice and the earliest removal
target. Normal removal requires at least one published release containing the
notice.

## Rollback plan

Describe how the deprecation or removal can be reversed safely.

## Owner

Name the command owner responsible for later lifecycle transitions.

## Approval evidence

Record repository-maintainer approval with enough local context to identify the
approver, decision, and date. A provider link is optional.

## Relevant links

List relevant repository-relative references. Explain explicitly when no
relevant link exists.

## Urgent security exception

State `Not used` for the normal path. For an urgent security removal, record all
of the following:

- rationale;
- user and operational impact;
- owner;
- repository-maintainer approval explicitly covering the exception;
- compensating migration guidance.
