# Experiment Control

## Fixed variables

- Same frozen scenario and seed repository.
- Same frozen operator answers, revealed after clarification output.
- Codex executor for both approaches.
- Model: `gpt-5.6-sol` with high reasoning effort when nested execution is
  available.
- Same workspace-write autonomy and no provider writes.
- Same documentation-only implementation boundary.
- Same completion criteria in `completion-criteria.md`.
- Same execution host, date window, and repository base commit.

## Deliberately varied variable

Only the workflow substrate varies:

- Axiom execution uses current `AGENTS.md`, `.agents/`, constitution, project
  context, architecture, decisions, research, and specifications.
- Spec-Kit execution uses the official Codex integration generated by pinned
  Spec-Kit release `v0.16.2`.

## Sequence and contamination control

1. Freeze scenario, operator answers, controls, and checksums.
2. Execute Axiom intake/specify/clarify; record questions; then reveal answers.
3. Complete Axiom plan/tasks/implementation/review/reconciliation without later
   improving the workflow.
4. Initialize a fresh copy of the same seed with pinned Spec-Kit.
5. Execute the official full Spec-Kit sequence; reveal the same answers only
   after clarification questions are recorded.
6. Do not edit an approach's outputs after observing the other to improve its
   score. Only factual annotations and copied evidence may be added outside the
   execution workspace.

## Unavoidable differences

- Workflow-specific instructions and generated scaffolding differ by design.
- Spec-Kit has named agent commands for each phase; Axiom uses routed repository
  skills and policies.
- If nested Codex execution cannot run, the active Codex session performs both
  flows sequentially and the limitation is recorded.
- Wall-clock duration includes tool startup and is approximate; it is not a
  controlled performance benchmark.
